# x32-mixer-emulator

Behringer X32 emulator in Python, based on `X32.c` by Patrick-Gilles Maillot
(github.com/pmaillot/X32-Behringer). It speaks OSC over UDP on port 10023, like the real console.
It has no audio: it simulates levels so the meters react to what you do on the console.

License: the original is GPLv3, so this port is too.

## Running

    python -m x32emu -v              # listens on 0.0.0.0:10023
    python -m x32emu --console X32RACK --state my_console
    python -m x32emu --no-sim        # no level simulation: meters and RTA stay silent

Requires Python 3.10 or newer. No external dependencies.
The state is saved on exit (Ctrl-C or `/-stat/lock ,i 2`) and read on the next start,
in a folder (by default `x32_state/`) with one file per section:

    x32_state/
      config.json  prefs.json  stat.json  headamp.json  outputs.json  show.json ...
      ch/01.json ... ch/32.json        auxin/01..08   fxrtn/01..08
      bus/01..16   mtx/01..06   dca/1..8   fx/1..8   main/st.json  main/m.json

Each file holds the prefix and the values with a relative address, for example in `ch/01.json`
`"mix/fader": 0.75`. The values are the console's (0..1, enum indices), not text.
A `--state file.json` still uses the old single-file format.

## What is implemented

- `/info`, `/xinfo`, `/status`
- get/set of every parameter (16,387, extracted from the C tables), with or without a type tag;
  enums accept a number or text (`/ch/01/gate/mode ,s GATE`)
- multi-argument set on a node (`/ch/01/eq/1 ,ifff 2 0.5 0.5 0.4`)
- `/node` and `/` with the console's text format (`-oo`, `+3.5`, `1k78`, `%00000101`)
- `/xremote` (up to 4 clients, 10 s), propagated only when the value changes
- `/subscribe`, `/formatsubscribe` (with `*`), `/renew`, `/unsubscribe`, `/meters/0` to `/meters/15`,
  `/batchsubscribe` for meters
- `/showdump` (only the show header; no scenes yet)
- packets without padding or type tag (e.g. `b"/xremote"`), as the real console accepts
- effects: all 61 types, with the parameters of each one (name, range, steps, enums);
  when the type changes the parameters go back to a neutral value and are sent to the clients

## Capturing a real X32 (read-only)

    python -m x32emu.capture --ip 192.168.1.50
    python tools/compare_capture.py capture_20261102_183000

The capture only sends read requests (`/info`, `/status`, `/node`, `/showdump` and a "get" for each
parameter, without arguments). A barrier in the code refuses anything else: it never sends
`/`, `/save`, `/load`, values, or anything in `/-action`. It writes to a `capture_<date>/` folder:
`nodes/` (scene text per section), `values/` (OSC type and value of each parameter),
`showdump.txt`, `no_reply.txt` (what does not exist in that firmware) and `info.json`.
With `--listen 60` it also records, for 60 s, the changes made on the console or in X32-Edit.
On Wi-Fi use `--window 4` to avoid losing packets.

`compare_capture.py` loads that state into the emulator and lists what differs: OSC types,
text format of each node and parameters the console does not know.

## Level simulation

Each channel receives pink noise with "phrases" (signal blocks and pauses). The level goes through
headamp gain, trim, low cut, EQ (computed analytically over the pink spectrum),
inserted effect, gate, compressor, fader, mutes, DCAs, pre/post sends, buses, matrices and main.

Effects: inserted GEQ/TEQ really change the level (31 third-octave filters); LIM limits;
FX1–4 fed by a bus return signal on the FX returns, which go into the mix.

Matrices are fed by the buses, main LR and mono (on/level/type of each send, pre or post).
Mutes (button, mute groups and muted DCAs) cut the output and all sends, including pre-fader ones;
the channel's pre-fader meters still show signal, like on the console.
DCAs: the meter is the members' highest post-fader level (`/meters/5` with group bank 0).
The other effects only apply their output gain, if they have one.

RTA (`/meters/15`): the source comes from `/-stat/rtasource` (0–71 pre-EQ, 98+ post-EQ); it shows the
source's pink noise and, post-EQ, that channel's EQ curve.

## Not implemented yet

`/batchsubscribe` outside meters, scenes/snippets/libraries (`/save`, `/load`, `/copy`...),
USB, real default values of each effect.

## Layout

    x32emu/data/          tables (generated by the scripts in tools/):
        index.json             section order
        params/<section>.json  parameter tree (ch.json, bus.json, prefs.json, ...)
        enums.json             value lists
        frequencies.json       exact /node frequency tables
        fx/<TYPE>.json         parameters of each effect (HALL.json, D-RV.json, ...)
    x32emu/datafiles.py   reading/writing the tables and the state
    x32emu/osc.py         OSC encoding
    x32emu/formats.py     value <-> text conversions
    x32emu/model.py       parameter tree and corrections to the C code
    x32emu/audio.py       level simulation
    x32emu/server.py      UDP server
    x32emu/capture.py     read-only capture of a real console
    tools/extract_tables.py   generates data/params, enums and frequencies from the C code
    tools/build_fx.py         generates data/fx/ (C + x32-osc) and the fx_divergences.json report
    tools/compare_capture.py  compares a real capture with the emulator
    tools/parity.py           compares /node with the original C emulator (incomplete)
    tests/test_emulator.py    37 UDP integration tests

    python -m unittest tests.test_emulator -v

## Regenerating the tables

The tables in `x32emu/data/` are already in the repository; regenerate them only when a source
changes. Both scripts are run from the project root:

    python tools/extract_tables.py <X32-Behringer folder>
    python tools/build_fx.py <X32-Behringer folder> <x32FxConditional export.json>

- `<X32-Behringer folder>`: a checkout of github.com/pmaillot/X32-Behringer (it reads `X32.c` and
  `X32Fx.h`).
- `<x32FxConditional export.json>`: the effect definitions of x32-osc
  (github.com/markschwartzkopf/x32-osc) exported to JSON, an object keyed by effect type
  (`HALL`, `D/RV`, ...) with the list of parameters of each.

`build_fx.py` rewrites `x32emu/data/fx/` and also writes `tools/fx_divergences.json`, the list of
differences between the C code and x32-osc (type, range, enum, number of parameters). That file
is only a report for review: it is not read by the emulator and is not versioned.

See DIFFERENCES.md for what was corrected relative to the original and what is still to be confirmed.
